# UX/UI Backlog (Offline-first)

## Product Principles
1. Offline-first: создание и редактирование отчета должны работать без интернета.
2. Speed-first: интерфейс должен ускорять работу специалиста автоподбора.
3. Learnability: новый пользователь должен быстро понять сценарий работы.

## P0 (Critical)
1. Atomic local save
- What: все изменения отчета (поля, фото, аудио, теги) пишутся локально транзакционно.
- DoD: после принудительного закрытия приложение открывает последний консистентный черновик без потерь.

2. Autosave + explicit status
- What: авто-сохранение на ключевых действиях + статус `Сохранено локально`.
- DoD: при изменении данных статус обновляется <= 1 сек; нет "тихих" потерь.

3. Single flow for media annotation
- What: единый поток `Добавить фото -> Выбрать элемент -> Теги -> Комментарий`.
- DoD: нет лишних экранов/кнопок до выбора элемента; шаги идут в одном порядке везде.

4. Keyboard UX
- What: закрытие клавиатуры по tap вне поля и по свайпу вниз на всех формах.
- DoD: во всех экранах ввода клавиатура закрывается предсказуемо, без блокировки UI.

5. Form consistency
- What: унифицированные валидации и ошибки полей (VIN, госномер, пробег, дата и т.д.).
- DoD: одинаковый стиль ошибок, единые маски/форматы, кнопки действий корректно disabled/enabled.

## P1 (High)
1. Information hierarchy cleanup
- What: убрать дубли заголовков, выстроить 1 главный заголовок + контекстный подзаголовок.
- DoD: на каждом экране читается цель действия за 2-3 секунды.

2. Action system consistency
- What: единый стиль primary/secondary/destructive кнопок и иконок.
- DoD: важные действия визуально приоритетны, удаление не конфликтует с просмотром.

3. Integrated comment tools
- What: голос-в-текст и AI-помощь встроены в блок комментария как inline actions.
- DoD: инструменты доступны в контексте комментария без отдельного "тех" блока.

4. Draft/Completed list behavior
- What: четко развести сценарии "Черновики" и "Завершенные".
- DoD: в завершенных нет лишних destructive controls, в черновиках быстрый resume/edit.

## P2 (Medium)
1. Performance pass
- What: уменьшить rebuild heavy-экранов, вынести тяжелые операции из UI thread.
- DoD: скролл и переходы плавные на iPhone без заметных фризов.

2. Sync queue (future server upload)
- What: очередь выгрузки с retriable статусами (`pending`, `failed`, `synced`).
- DoD: отчеты создаются офлайн, выгружаются позже без дублей.

3. UX telemetry (local)
- What: локальная диагностика времени шага и точек отказа.
- DoD: есть метрики для оптимизации сценариев без внешней аналитики.

## First Iteration Scope (Start Here)
1. P0.2 Autosave + status.
2. P0.3 Единый медиа-поток "Фото -> Элемент -> Теги -> Комментарий".
3. P0.4 Закрытие клавиатуры tap/swipe во всех формах.

## Success Metrics
1. Median time to complete report: -25%.
2. Drop-offs inside "Осмотр/Заметка элемента": -40%.
3. Draft recovery success after force-close: 100%.
